2026-08-01 — Reload-time prompt-free session reconciliation fix

Diagnosis:
- An active match could become interactive after wallet reconnection while the
  encrypted browser session was still restoring. The move handler treated the
  transient `restoring` state as if prompt-free authorization were absent and
  immediately offered a primary-wallet move.
- Session identity was derived from the bracket or URL selection but not from
  the active match itself. During reload/navigation reconciliation this could
  briefly leave the session hook without the tournament instance, explaining
  why another navigation or reload appeared to fix the issue.
- The same generic prompt was used for temporary restoration, genuine local-key
  loss, and transport failure, obscuring whether a replacement-key transaction
  was actually required.

Fix:
- Bound all three game session hooks to the active match instance first.
- Added an authoritative move-time restore. A move now waits for encrypted-key
  and on-chain reconciliation and remains prompt-free when that succeeds; it
  does not show a wallet fallback prompt during the reload race.
- Added an explicit recovery path for missing, expired, rotated, revoked, or
  inactive sessions. The user is told that authorizing a replacement key is a
  one-time primary-wallet transaction, leaves tournament funds unchanged, and
  occurs before the intended move is submitted.
- Clarified that direct-wallet fallback confirms only the current move and does
  not regenerate the prompt-free key.
- Strengthened move eligibility so an inspection explicitly reporting no local
  key can never be treated as session-ready.

Validation:
- Added move-readiness coverage for reload restoration, accepted/declined key
  recovery, and one-move direct fallback, plus hook and session-status tests.
- The V3 release gate passed all 147 tests, the production build passed, and
  the security scan passed across 59 production source files.
- The production preview rendered `/v3/tictactoe` with the expected arena and
  wallet CTA. The temporary preview and browser tab were then stopped/closed,
  and port 3100 was verified clear.

2026-08-01 — Development CSP / React refresh crash

Diagnosis and fix:
- The production `script-src 'self'` policy had also been applied to Vite's
  development server. Vite injects an inline React Fast Refresh preamble, so
  the browser blocked it and `@vitejs/plugin-react` then crashed while loading
  components with “can't detect preamble.”
- Split the server headers by environment. Development permits
  `script-src 'self' 'unsafe-inline'` solely for Vite's injected preamble;
  production preview and deployed `_headers` retain strict
  `script-src 'self'` with no unsafe script directive.
- The MetaMask/SES “Removing unpermitted intrinsics” message is extension-side
  hardening output and was not the application crash.

2026-08-01 — Player-facing next-move gas card

Completed:
- Reframed the floating prompt-free card around the player's next move instead
  of session implementation details.
- On the player's turn with a usable sponsored session, the card now always
  shows the estimated network fee for the next move and explains that the move
  is expected to be sponsored, so the player's wallet should not be charged.
- The estimate uses current chain fee data and a conservative per-game move gas
  allowance. It refreshes while it is the player's turn, displays at most five
  decimal places, and renders any value below `0.00001 ETH` as `0 ETH`.
- Off-turn, the card shows a simple “Waiting for your opponent” state and waits
  to present a gas estimate until the player's turn.
- During reload restoration, the card shows a non-actionable checking state so
  it does not incorrectly imply that a wallet confirmation is already needed.
- When prompt-free moves are unavailable, the card says the gas cannot yet be
  estimated and explains that the wallet will show the estimate before the
  player approves the next move.
- Removed executor addresses, chain/session identifiers, JSON diagnostics, raw
  transport errors, and developer-oriented terminology from the visible card.

- Removed every CTA from the floating card. It is now status-only and cannot

  prompt-free submission, and then continues.
